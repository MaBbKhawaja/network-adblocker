# network-adblocker

Whole-home ad blocking on a £5 ESP32-S3, plus a browser extension for the one thing DNS can't touch: YouTube.

**What you get**
- Every device on the Wi‑Fi (phones, apps, TVs, laptops, guests) stops loading ads and trackers. Nothing is installed on
  the devices: the board answers their DNS questions and answers `0.0.0.0` for ~440,000 known ad and tracker domains.
- A dashboard at **http://adblocker.local** with per-device stats, names, pause buttons, editable allow/block lists,
  an on/off switch per board, and an internet health monitor with an outage log.
- A Chrome/Firefox extension (served by the board itself) that removes YouTube's in-video ads in browsers, with its rule
  list and counts coordinated by the board.
- If the board is unplugged the house keeps working: the router falls back to a public resolver, with ads, never without
  internet.

**What it can't do, and why** (network blockers, Pi-hole included, all share these)
- Ads inside YouTube, Instagram, TikTok, Facebook, X: they come from the same servers as the content, inside encryption.
  Browsers get the extension; phone apps need a different client (ReVanced, SmartTube) or the app's paid tier.
- The blank frame some apps show for a few seconds where the ad would have been: the app draws it itself.
- Anything while a commercial VPN is on: the VPN tunnel bypasses your Wi‑Fi's DNS entirely.
- Anything away from home. That needs a home VPN on an always-on computer (planned: Raspberry Pi 5 + Tailscale).

## Hardware

- **ESP32-S3 dev board with 8 MB PSRAM and 16 MB flash** (module marked `ESP32-S3-WROOM-1 N16R8`). The PSRAM holds
  the blocklist; a board without it falls back to a 20k-domain list. Two identical boards are used here; one is enough.
- A USB **data** cable (charge-only cables light the board but the computer never sees it) and any USB charger.
- A router whose DHCP settings let you set the DNS servers. Here: Hyperoptic Hyperhub (Zyxel EX3301-T0).

## Step by step

### Step 1 · Tools on the computer (once)

```bash
brew install arduino-cli            # macOS; Linux: see arduino.github.io/arduino-cli
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32
```
Also needed: `python3` (macOS has it) and `dig` for testing (macOS has it).

### Step 2 · Fill in `.env`

```bash
git clone https://github.com/MaBbKhawaja/network-adblocker.git
cd network-adblocker
cp .env.example .env
```
Edit `.env`:
- `WIFI_SSID`, `WIFI_PASSWORD`: your Wi‑Fi.
- `NETMON_IP`: a fixed address **outside the router's DHCP pool** (here the pool is .100–.254, the board is .53).
  `NETMON_GATEWAY` is the router, usually `192.168.1.1`.
- `ROUTER_URL/USER/PASSWORD`: from the card on the router. Only used by you; the firmware never sees them.
- `OTA_PASSWORD`: any random string; it lets you update the board over Wi‑Fi later.
- Leave `NTFY_TOPIC` empty unless you want phone pushes (see step 8).
- Second board: `NETMON2_HOST`, `NETMON2_IP`, `NETMON_PEERS` / `NETMON2_PEERS` (each board's list of the others).

### Step 3 · Flash the board over USB (once per board)

1. Plug the board into the computer with a data cable. `arduino-cli board list` shows it as an ESP32 on
   `/dev/cu.usbmodem…`; put that port in `NETMON_SERIAL_PORT`.
2. Build and flash:
   ```bash
   ./build.sh secrets     # writes netmon/secrets.h from .env
   ./build.sh all         # packs the extension, compiles (~2 min), uploads
   ./build.sh monitor     # optional: watch it boot (Ctrl-C to leave)
   ```
3. Wait about a minute. The LED goes blue (connecting) then green (internet OK). Open **http://adblocker.local**
   (or `http://<NETMON_IP>/`). The first boot downloads the three blocklists, which takes about 80 seconds; the badge
   then says **BLOCKING** with a domain count. The list is cached in flash, so later boots take seconds.
4. Move the board to any USB charger. It only needs the computer for this first flash.

For a second board: `NODE=2 ./build.sh all` with the second board on USB.

### Step 4 · Test the board on one device

From the computer:
```bash
dig +short doubleclick.net @192.168.1.53      # -> 0.0.0.0        (blocked)
dig +short bbc.co.uk       @192.168.1.53      # -> a real address (allowed)
```
Or set the DNS of one phone to the board's address by hand and open a free game: ad slots stay empty and the
dashboard's **Recent queries** shows red BLOCKED rows.

### Step 5 · Point the router at it (makes it work for everyone)

In the router admin (Hyperhub: https://192.168.1.1, `admin`, password from the card):
1. **Network Setting → Home Networking → LAN Setup**.
2. **DNS Values**: mode **Static**. **DNS Server 1** = the board (`192.168.1.53`).
   **DNS Server 2** = `1.1.1.1`. Slot 2 is what keeps the house online if the board is unplugged; a device only asks
   it when the board doesn't answer, so ads still get blocked almost all the time.
3. Make sure the board's address is outside **IP Addressing Values** (the DHCP pool).
4. If there is a **LAN IPv6** section, set it to disabled or its DNS to none; otherwise phones can ask the router
   over IPv6 and bypass the board.
5. **Apply**. Devices pick it up when they reconnect to Wi‑Fi or within one lease (24 h here).

Check: reconnect a phone's Wi‑Fi, open the dashboard, and the phone appears in **Devices**.

Two per-device bypasses to switch off if a device still sees ads: iCloud Private Relay (iPhone: Settings → your name →
iCloud → Private Relay) and Android "Private DNS" set to a provider (set it to Automatic).

### Step 6 · YouTube in browsers: the extension

Video ads inside YouTube can't be blocked by DNS, so laptops get a small extension:
1. On the laptop open **http://adblocker.local/extension**, download the zip, unzip, keep the folder somewhere permanent.
2. Chrome/Edge/Brave: `chrome://extensions` → Developer mode → **Load unpacked** → choose the folder (or drag the folder
   onto the page). Firefox: see `extension/README.md`.
3. Open a YouTube video. Within a minute the dashboard's **YouTube ads** section lists the laptop with an "ads removed"
   count. Rules come from the board, so the extension never needs updating by hand.

The dashboard flags devices that open YouTube in a browser **without** the extension. The **Require the extension**
switch goes further: such browsers get "site can't be reached" for youtube.com until they install it. Before turning it
on, add phones and TVs to **Exempt from the YouTube rule** (they can't run extensions; give them fixed addresses in the
router's Static DHCP first).

### Step 7 · Daily use: the dashboard

- **Boards**: each board with ONLINE/OFFLINE and its own **Turn off / Turn on** (off = forwards everything, blocks
  nothing, still answers so nobody loses internet; the other board is unaffected).
- **Ad blocker**: totals, **Pause 5 min / 1 hour / Resume** for the whole house, **Update list**.
- **Devices**: click a device to name it; **Pause 1h** per device; a YouTube-extension yes/no column.
- **Settings**: **Always allow** (a site and its subdomains), **Always block**, **Exempt from the YouTube rule**.
  Saved on the board, applied instantly, no reflash. A site broken by the blocker: watch Recent queries while you
  reproduce it, then add the offending domain to Always allow.
- **Internet**: latency to the router, Cloudflare and Google, DNS time, sparklines, and an outage log. LED: green OK,
  amber degraded, red internet down, pink router unreachable, blue connecting.

### Step 8 · Updates and changes later

- **Firmware over Wi‑Fi**: `./build.sh ota` (first board), `NODE=2 ./build.sh ota` (second). No cable.
- **Blocklists**: edit `BLOCKLIST_URLS` in `netmon/dnsconfig.h`, then `./build.sh ota`. Accepts hosts format, plain
  domains, `*.domain` wildcards and AdGuard `||domain^`. Budget ~480k unique domains; the three lists here total ~440k.
- **YouTube rules**: edit `netmon/ytguard.h`, bump `YT_RULES_VERSION`, `./build.sh ota`; browsers refresh within 5 min.
  uBlock Origin's filter list is the reference for current key names when YouTube renames something.
- **Local names** (e.g. `nas.home` → an IP): `LOCAL_NAMES` in `netmon/dnsconfig.h`.
- **Phone pushes**: set `NTFY_TOPIC` in `.env` to a topic on ntfy.sh and `./build.sh ota`; the board then pushes
  outage notices and "this device needs the extension" notes.

### Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Whole house "connected, no internet" | Both boards off and no fallback in DNS Server 2. Plug a board in, or set DNS Server 2 = 1.1.1.1 as in step 5. |
| A phone still sees ads | It isn't asking the board (not in Devices): reconnect Wi‑Fi, check Private Relay / Private DNS, check the router's IPv6 DNS. |
| A site or app broke | Recent queries → find the blocked domain → Always allow. |
| Board shows OFFLINE on the dashboard | Unplugged, or older firmware: `./build.sh ota`. |
| Computer never sees the board on USB | Charge-only cable. The factory LED demo (purple/green) still lights up. |
| "Disable developer mode extensions" bubble in Chrome | Normal for an extension not from the store; choose to keep it. |
| YouTube "site can't be reached" on a laptop | Require the extension is on and this laptop hasn't installed it: http://adblocker.local/extension. |

## API (all boards, JSON)

`GET /api/status` · `GET /api/history` · `GET /api/dns` · `POST /api/pause?min=N` · `POST /api/resume` ·
`POST /api/update` · `POST /api/blocking?on=1|0` · `GET /api/lists` ·
`POST /api/lists?list=allow|block|exempt&add=…|remove=…` · `POST /api/device?ip=…&name=…` ·
`POST /api/device?ip=…&pause=MINUTES` · `GET /api/yt` · `GET /api/yt/rules` · `POST /api/yt/stats` ·
`POST /api/yt/enforce?on=1|0` · `GET /extension` · `GET /extension/ytguard.zip`
